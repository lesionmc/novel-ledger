# ai-novel-workbench · 中文 AI 小说共创写作台

帮人把**长篇**中文小说写完的工具：AI 一章一章续写，作者全程把关（定大纲、审章节、拍板发布）。一句话——**解决大模型写长篇的两个致命病**：

| 病 | 症状 | 药 |
|---|---|---|
| **失忆崩坏** | 第 1 章埋的伏笔第 20 章忘回收；角色串戏；时间倒流；道具"漂移"（徽章写着写着变袖扣） | **滚动状态账本**（记忆中枢） |
| **AI 腔** | "微微/轻轻"满天飞、"夜色如墨"、雨刷刮水雾反复收尾、破折号泛滥 | **去 AI 味引擎**（检测 + 改写） |

纯 Python 标准库实现，**零第三方依赖**，任何 OpenAI 兼容模型即插即用（Agnes / 智谱 / DeepSeek …）。

## 快速开始（5 分钟跑通）

```bash
# 1. 准备：复制配置模板并填 key
cp .env.example .env        # Windows: copy .env.example .env

# 2. 建一本书：复制 sample_book/ 里的 设定.md/角色卡.md/大纲.md 三件套，改成你的故事
#    （书 = 一个文件夹，放 books/ 下）

# 3. 初始化记忆账本（只跑一次）
python scripts/write_chapter.py --book books/雾城档案 --init-state

# 4. 写第 1 章（之后 --chapter 2/3/4… 一路连写）
python scripts/write_chapter.py --book books/雾城档案 --chapter 1

# 5. （可选）写完后做一致性审计：对照账本查本章正文的冲突/漏记
python scripts/write_chapter.py --book books/雾城档案 --audit --chapter 6

# 6. （可选）写完做 AI 腔体检 → 出报告 → 人工确认后应用改写
python scripts/deai.py --scan books/雾城档案                  # 全书体检（零成本）
python scripts/deai.py --polish books/雾城档案 --chapter 5    # 单章精判，出报告
python scripts/deai.py --apply books/雾城档案 --chapter 5     # 应用改写（自动备份）

# （开发者）零网络冒烟测试，改代码后回归用
python scripts/smoke_test.py
```

## 一本书 = 一个文件夹

```
books/我的书/
├─ 设定.md          # 创作宪章：世界观、能力规则、写作约束
│                   #   ⚠ 关键道具外观必须在此写死（防 AI 漂移成别的）
├─ 角色卡.md        # 角色：名字/身份/性格/关系
├─ 大纲.md          # 全书主线 + 卷/章细纲
├─ chapters/        # 正文：ch001.md ch002.md …（不入 git）
├─ story_state.md   # ★ 滚动状态账本（机器维护，作者可手改）
└─ chXXX.AI腔体检.md # 去味报告（polish 产物）
```

## 命令手册

### 连载引擎 `scripts/write_chapter.py`

| 命令 | 作用 |
|---|---|
| `--book <书目录> --chapter N` | 写第 N 章：自动注入配方，写完后自动更新账本 |
| `--init-state` | 按三件套初始化 story_state.md（开书跑一次） |
| `--state-only` | 只重算账本不写正文（账本漏更时补救） |
| `--audit`（配 `--chapter N`） | 一致性审计：对照账本检查第 N 章正文的冲突/漏记，报告落盘 `chXXX.一致性审计.md`（不改文件） |
| `--no-state` | 写正文但跳过账本更新（调试用） |
| `--model/--base-url/--reasoning-effort` | 换模型/换思考预算（默认读 .env） |

> **备用模型自动切换**：主模型连续失败后，引擎自动改用 `.env` 里配置的
> `FALLBACK_API_KEY / FALLBACK_BASE_URL / FALLBACK_MODEL`（防单点故障，详见 `.env.example`）。

### 去 AI 味引擎 `scripts/deai.py`

| 命令 | 作用 |
|---|---|
| `--scan <书目录>` | L1 词表硬筛全书：AI 腔指数 + 命中清单 + 跨章意象提示（本地跑，零 token） |
| `--polish <书目录> --chapter N` | L2 AI 精判单章：出人读报告 + 机读 diff JSON（不改正文） |
| `--apply <书目录> --chapter N` | 按 diff 应用改写：**自动备份原稿**到 `.bak.md`，只改 hard 级病句 |

> **安全原则**：`--apply` 只自动应用「hard 级硬伤」（如"夜色如墨""说不清道不明"这类几乎必腔的），改写前自动备份；soft 级文风问题（副词高频、破折号密度、意象复用）只出报告和示范建议，交给作者人工斟酌。

## 原理（大白话）

### 1. 上下文配方 —— 不把整本书塞给 AI

写一章只喂五样：**创作宪章 + 当前卷大纲 + 活跃角色卡 + 记忆 + 上一章结尾 800 字**。AI 的注意力是有限的，喂太多反而乱；喂"精华 + 当前需要的碎片"最稳。

### 2. 滚动状态账本 —— 治长篇失忆

每写完一章，AI 读「旧账 + 本章正文」，**整体重写一本新账**（覆盖式，不是越加越长）。账本固定 7 个小节：

```
当前时间 / 计数与资源 / 角色状态 / 关键事件时间线
/ 伏笔账本 / 关键物件 / 待续状态
```

好处：① 上下文永远恒定，写第 50 章和写第 2 章的负担一样；② 计数会核对（回闪 1 天 3 次超没超）、伏笔会自动标记"已回收"、道具外观写死后严禁改动；③ 账本是 Markdown，作者随时能手动改（比如直接指定下一章接哪）。

### 3. 去 AI 味 —— 两级检测

- **L1 词表硬筛**（本地、零成本、可解释）：内置「AI 腔黑名单」（分 hard/soft 两级），加破折号/省略号密度、跨章意象复用统计，输出**每章 AI 腔指数**。
- **L2 AI 精判**（调模型）：只把命中句和它的局部上下文喂给模型，逐句判定"真 AI 腔 / 正常表达"，真病句才给改写。所以"不是…而是…"这种正常推理句式会被正确放行，不误伤。

### 4. 人机共创 —— 机器干活，人把关

AI 负责起草、自查、改写建议、记忆回填；人在闸口：定大纲、审章节、**确认改写是否应用**、拍板发布。这也是产品定位（也是平台合规要求）：AI 是笔，人是作者。

## 踩过的坑（给后来者省时间）

1. **推理模型"思考失控"**：agnes-2.5-flash 在长上下文 + 长创作指令下，reasoning 会吞光 `max_tokens`，返回空正文（`finish_reason=length`）。**解法：请求加 `reasoning_effort=low`**（实测思考从 12000 → 419 tokens）。
2. **输入超 ~5k tokens 又触发失控**：更新账本时把整章 5500 字塞进去就崩。解法：账本更新只喂正文**首尾各一段**（账本只需要"本章事实增量"），并把 `max_tokens` 提到 12000。
3. **低版本模型不守边界**：agnes-2.0-flash 一口气写 1.7 万字跨多章、称呼串戏（把前妻叫"老陈"）。主力用 2.5-flash + reasoning low。
4. **Python 字符串里的引号地狱**：中文提示词里嵌英文双引号会截断字符串（SyntaxError）。写提示词用「」或全角引号。
5. **截尾记忆会穿帮**：早期每章只留 400 字摘要，模型会"凭空编造上一章没发生的事"（第 2 章编出"潜入办公室"）。结构化滚动账本根治。
6. **道具漂移**：设定文档没写死外观，徽章跨版本从"荆棘眼"漂成"鸟形袖扣"。**设定.md 必须把关键道具外观写死** + 账本规则禁止改动。
7. **词表要实战校准**：初版把"若有若无""不是X而是Y"当必腔，实测发现形容气味/推理对比场景是正常表达 → 降为"高频才报"。
8. **AI 改 AI 会引入新套话**：改写把"某种说不清的金属味"换成"若有若无的铁锈气"，而后者也在词表里。**规矩：apply 后必须 re-scan 复查**。
9. **文本替换锚会吞引号**：对话句以引号开头时，自动切句把引号包进去、改写版没引号 → 替换丢引号破坏格式。句子边界要把引号算上。
10. **.env 别入库**：key 只放本地 .env（已在 .gitignore）。
11. **Windows 控制台乱码/打印报错**：脚本带 ⚠/✅ 等非 GBK 字符，若在旧控制台（代码页 936）打印崩，设环境变量 `PYTHONUTF8=1` 再跑。
12. **主/备用通道务必两家厂商**：failover 只在主通道彻底失败时切换；同厂商同账号会连坐（限流/服务宕机一起挂）。
