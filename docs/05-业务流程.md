# 05 · 业务流程

本文档为项目复盘补写，技术事实以代码为准（依据：`scripts/write_chapter.py`、`scripts/deai.py`、`web/server.py`、`web/static/app.js`）。

novel-ledger 的日常使用只有三条主流程，全部围绕「**一本书 = 一个文件夹**」展开：

| 流程 | 入口（CLI） | 入口（Web） | 产物 | 是否改正文 |
|---|---|---|---|---|
| ① 单章连写 | `write_chapter.py --book … --chapter N` | 书内「✍ 写下一章」 | `chXXX.md` + 更新 `story_state.md` | 是（新增/覆盖正文 + 覆盖账本） |
| ② 去 AI 味 | `deai.py --scan / --polish N / --apply N` | 书内「🔬 全书体检」等 | `chXXX.AI腔体检.md`、`chXXX.AI腔diff.json`、`chXXX.bak.md` | 仅 `--apply` 改正文 |
| ③ 一致性审计 | `write_chapter.py --audit --chapter N` | 书内「一致性审计」 | `chXXX.一致性审计.md` | 否（只读） |

> 三条流程共用同一份记忆中枢 `story_state.md`：① 写它、② 不动它、③ 读它。这也是它们必须按「① → ③ → ②」顺序跑的原因：**先保证事实对（审计），再保证文笔顺（去味）**——反过来会把腔调改对了、事实却错着的章节误判为「可用」。

## 一、流程 ① 单章连写（连载引擎）

### 1.1 ASCII 流程图

```

   开书（仅一次）────▶ │ write_chapter.py --init-state │
                      └──────────────┬───────────────┘

                                     ▼
                      ┌──────────────────────────────┐
                      │  生成 story_state.md（初始账）│
                      └──────────────┬───────────────┘
                                     │
  ═══════════════════════════════════╪═══════════════════════════════════
   每章循环                          ▼
                      ┌──────────────────────────────┐
                      │ [1/4] build_context()        │
                      │  创作宪章(设定.md)            │
                      │ + 全书大纲(大纲.md)           │
                      │ + 活跃角色卡(角色卡.md)       │
                      │ + 全书记忆账本(story_state)   │
                      │ + 上一章结尾 800 字           │

                      └──────────────┬───────────────┘
                                     ▼
                      ┌──────────────────────────────┐
                      │ [2/4] call_llm()             │
                      │  temperature 0.85            │
                      │  max_tokens 12000            │
                      │  reasoning_effort=low        │
                      │  ├─ 主模型 重试 2 次          │
                      │  └─ 全败 → 切 FALLBACK_*     │
                      └──────────────┬───────────────┘
                                     │ 正文（约 3000 字）
                                     ▼
                      ┌──────────────────────────────┐

                      └──────────────┬───────────────┘
                                     │

                      │  输入 = 旧账 + 本章正文        │

                      │  temperature 0.2 / 重试 3 次  │
                      │  输出 = 完整新账（覆盖式）     │
                      └──────────────┬───────────────┘
                                     ▼
                      ┌──────────────────────────────┐

                      └──────────────┬───────────────┘
```

### 1.2 步骤表

| # | 步骤 | 谁做 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|---|
| 1 | 建书 | 人（或 Web 建书向导） | `sample_book/` 三件套 | `books/<书名>/{设定,角色卡,大纲}.md` | 无三件套直接写章也能跑，但上下文缺料 → 必补 |
| 2 | 初始化账本 | 引擎 `--init-state` | 设定+角色卡+大纲 | `story_state.md`（初始账，temperature 0.2 / max_tokens 4000） | 不建账本直接写章：上下文会注入「提醒」句，且续写无记忆 → 立刻补跑 |
| 3 | 组装上下文 | `build_context()` | 三件套 + 账本 + 上一章（编号 **小于** 本章的最近章） | 单条 prompt | 缺文件不报错，静默少一块 → 用冒烟测试第 5 组断言兜底 |
| 4 | 生成正文 | `call_llm()` | prompt | 正文文本 | 主模型重试 2 次仍败 → 自动切 `FALLBACK_*`；备用也败 → `RuntimeError`，正文不落盘 |
| 5 | 落盘正文 | 引擎 | 正文 | `chapters/chXXX.md`（`ch{no:03d}.md`） | 目录不存在会 `FileNotFoundError`（Web 侧 `PUT /ch/{no}` 会自动 `makedirs`，CLI 侧不会） |
| 6 | 更新账本 | `update_state()` | 旧账 + 本章正文 | 完整新账全文 | 失败则正文已写、账本滞后 → 用 `--state-only --chapter N` 补救 |
| 7 | 人工过闸 | 人 | 正文 + 账本 | 手改正文/账本，`Ctrl+S` 或 `PUT` 保存 | 不审就续写 → 错误会被账本固化并放大到后面每一章 |

> **Web 侧的额外保护**：`POST /api/book/{book}/write` 在发现缺 `story_state.md` 时会先自动跑一次 `--init-state` 再写章，CLI 侧没有这个兜底。

### 1.3 关键设计点（写流程）

| 点 | 代码事实 | 为什么 |
|---|---|---|
| 上一章结尾只取「编号更小的最近章」 | `prior = [f for f in legacy if chapter_no_of(f) < chapter_no]` | 回写重写第 N 章时，N+1 已存在；若取全局最新会拿「未来章」结尾续写第 N 章 |
| 结尾 800 字 | `DEFAULT_CHUNK_END = 800` | 只取尾部，控制输入规模 |
| 账本更新只喂首尾 | 正文 >3200 字 → 前 1400 + 省略提示 + 后 1400 | 防输入超 ~5k tokens 触发 reasoning 失控（详见 `06-技术方案.md`） |
| 提示词用 `replace` 不用 `format` | `.replace("{STATE_FILE}", …)` 等 | 正文/账本含花括号时 `format()` 会抛 `ValueError/KeyError` |
| 账本是覆盖式重写 | `STATE_UPDATER_PROMPT` 规则 1 | 上下文恒定，写第 50 章与第 2 章负担相同 |

## 二、流程 ② 去 AI 味（两级检测 + 安全应用）

### 2.1 ASCII 流程图

```
  ┌───────────────────────────────────────────────────────────────┐
  │ L1 · --scan（本地，零 token，全书）                            │
  │   逐行扫 AI_TONE_BLACKLIST(hard) + HARD_PATTERNS(正则)         │
  │   全文计数 soft 词 / SOFT_PATTERNS → ≥2 才算高频               │
  │   破折号、省略号密度（每千字 2.0 / 1.5 超阈即报）              │
  │   IMAGE_WORDS 跨章复用（总次≥3 且 跨章≥2 才提示）              │
  │   指数 = (hard×2 + soft项 + 标点超标项) ×1000 / 字数           │
  └───────────────────────────┬───────────────────────────────────┘
                              │ 控制台出指数报告（不落盘）
                              ▼
  ┌───────────────────────────────────────────────────────────────┐
  │ L2 · --polish N（调模型，单章）                                │
  │   只喂「命中句 + 该行原文」的局部上下文（不喂全文）             │
  │   → 模型返回 JSON 数组 [{idx, verdict, rewrite, reason}]       │
  │   解析失败 → 正则截 [ … ] 再解；仍失败 → SystemExit            │
  ├───────────────────────────┬───────────────────────────────────┤
  │ 人读：chXXX.AI腔体检.md    │ 机读：chXXX.AI腔diff.json          │
  │ （ai / ok 两栏 + 意象提示）│ （仅 hard 级 且 verdict=ai 的项）  │
  └───────────────────────────┴───────────────┬───────────────────┘
                                              │ 人看完报告拍板
                                              ▼
  ┌───────────────────────────────────────────────────────────────┐
  │ --apply N（本地，零 token）                                    │
  │   ① 首次应用前备份原稿 → chXXX.bak.md（已存在则不覆盖）         │
  │   ② 逐条：orig 必须是 lines[line-1] 的精确子串，否则跳过        │
  │   ③ 只替换一次（replace(orig, rewrite, 1)）                    │
  │   ④ 打印 ✅成功 / ⚠️跳过（含原因）                              │
  └───────────────────────────┬───────────────────────────────────┘
                              ▼
                   【必须】re-scan 复查（AI 改 AI 会引入新套话）
```

### 2.2 步骤表

| # | 步骤 | 谁做 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|---|
| 1 | 全书体检 | 引擎 `--scan` | `chapters/ch\d{3}.md` | 控制台指数报告（**不落盘**） | 目录无 `chapters/` 时退回书目录本身匹配 `chXXX.md`（`chapter_files()` 兼容逻辑） |
| 2 | 挑章精判 | 引擎 `--polish N` | L1 命中清单 + 该章原文行 | `chXXX.AI腔体检.md` + `chXXX.AI腔diff.json` | 章不存在 → `SystemExit` 列出目录现有章；无 API key → `SystemExit("缺少 AGNES_API_KEY")` |
| 3 | 模型返回解析 | 引擎 | 模型原文 | `verdicts` 列表 | 非 JSON → 正则截取 `[…]`；仍失败 → 退出并打印前 500 字符 |
| 4 | 人工确认 | 人 | 人读报告 | 决定应用 / 手改 / 放弃 | 报告里有「正常表达（保留）」栏，别误杀 |
| 5 | 应用改写 | 引擎 `--apply N` | `chXXX.AI腔diff.json` | 改写后的 `chXXX.md` | 无 diff → `SystemExit` 提示先跑 `--polish`；diff 为空 → 打印「无需应用」返回 0 |
| 6 | 复查 | 人 | 改写后正文 | 重跑 `--scan` | 若新套话（如「若有若无」）上了榜 → 手动改或退回 `.bak.md` |

### 2.3 安全边界（去味流程的三道闸）

| 闸 | 代码依据 | 效果 |
|---|---|---|
| 只自动改 hard 级 | `if v.get("verdict") == "ai" and v.get("rewrite") and v.get("idx") in hard_idx_map` | soft 级（副词高频、破折号密度、意象复用）只出示范，绝不自动改 |
| 整句锚点精确匹配 | `if orig not in cur: skipped.append(...)` | 匹配不上就跳过，不做模糊替换 |
| 备份只留首版 | `if not os.path.exists(bak_path): 写备份` | 第一次应用前的原稿永久保留；重复 apply 不会把中间态覆盖进去 |

> ⚠ **已知副作用**：因为 `.bak.md` 只在**不存在时**创建，若对同一章先 apply、再手改、再 apply，`.bak.md` 里是**第一次**的原稿，不含后续手改内容。手改前请自行另存（详见 `11-操作手册.md` 备份章节）。

## 三、流程 ③ 一致性审计（只读）

### 3.1 ASCII 流程图

```
  ┌────────────────────────────┐
  │ --audit --chapter N        │
  └────────────┬───────────────┘
               ▼
  ┌────────────────────────────────────────────────┐
  │ 前置校验                                        │
  │  缺 story_state.md → SystemExit「无法审计」     │
  │  缺 chXXX.md       → SystemExit「缺章节正文」   │
  └────────────┬───────────────────────────────────┘
               ▼
  ┌────────────────────────────────────────────────┐
  │ 输入瘦身                                        │
  │  ① 账本：正则剥掉「## 伏笔账本」整节             │
  │     （伏笔状态由账本更新器规则 9 自查）          │
  │  ② 正文：>3200 字 → 首尾各 1400                 │
  └────────────┬───────────────────────────────────┘
               ▼
  ┌────────────────────────────────────────────────┐
  │ call_llm（temperature 0.1 / max_tokens 12000）  │
  │ AUDIT_PROMPT：冲突 / 漏记 / 存疑 三类           │
  │ 每条给：位置 + 问题描述 + 建议改法              │
  └────────────┬───────────────────────────────────┘
               ▼
  ┌────────────────────────────────────────────────┐
  │ 落盘 chapters/chXXX.一致性审计.md               │
  │ 「未改动账本与正文」（只读审计）                 │
  └────────────┬───────────────────────────────────┘
               ▼
        人按报告决策：改正文 或 改账本（手改 story_state.md）
```

### 3.2 步骤表

| # | 步骤 | 谁做 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|---|
| 1 | 触发审计 | 人 / Web | 章号 N | — | 章号 <1 时 CLI 会先判「请指定 --chapter N」；Web 侧 `no<1` → 400「需要 no」 |
| 2 | 前置校验 | 引擎 | 账本、正文 | — | 缺任一 → `SystemExit`；Web 侧审计前会自动补跑 `--init-state` |
| 3 | 输入瘦身 | 引擎 | 旧账、正文 | 精简 prompt | 剥节后若为空则回退用完整账本（`if not old_state_core: …`） |
| 4 | 模型审计 | 引擎 | prompt | 审计清单文本 | 同 `call_llm` 主备 failover（重试 3 次） |
| 5 | 落盘报告 | 引擎 | 清单文本 | `chXXX.一致性审计.md` | — |
| 6 | 人工裁决 | 人 | 报告 | 改正文 / 改账本 / 标记忽略 | 账本里出现 `⚠冲突：旧账记X，本章写Y（请作者裁决）` 时必须人工介入 |

### 3.3 审计的三类产出与处置

| 类别 | 含义（AUDIT_PROMPT 定义） | 处置人 | 典型处置 |
|---|---|---|---|
| 冲突 | 正文与账本矛盾：时间倒退/跳跃、计数对不上、角色状态或位置矛盾、物件归属或外观冲突、已回收伏笔又当未解用 | 人 | 二选一：改正文字句，或改账本条目 |
| 漏记 | 本章发生了应入账的事实（新角色、新物件、重要决定、新伏笔）但账本没有 | 人 | 手改账本补条目，或跑 `--state-only --chapter N` 让模型重算 |
| 存疑 | 模型拿不准但值得看一眼 | 人 | 视情况忽略 |

## 四、状态流转表

### 4.1 章节状态

判据全部可落盘验证（不依赖数据库，纯文件系统）。

| 状态 | 判据（文件系统） | 由谁推进 | 可执行的下一步 |
|---|---|---|---|
| **未写** | `chapters/chXXX.md` 不存在 | — | 写章（CLI `--chapter N` / Web「写下一章」） |
| **草稿** | `chXXX.md` 存在（`ch{no:03d}.md`） | 写章流程 ① | ③ 审计 → ② 体检 → 人工编辑 |
| **已审计** | 存在 `chXXX.一致性审计.md` | 流程 ③ | 按报告改正文或账本；未处理完不要续写下一章 |
| **已体检** | 存在 `chXXX.AI腔体检.md` | 流程 ② `--polish` | 看报告 → `--apply` 或手改 |
| **已应用** | 存在 `chXXX.bak.md` 且 apply 日志「成功应用 ≥1 处」 | 流程 ② `--apply` | **必须 re-scan 复查**；有新套话就退回 `.bak.md` |
| **已定稿**（本项目未设标志位，靠人记） | 上述流程都过且人工确认 | 人 | 发布 / 导出 |

```
  未写 ──写章──▶ 草稿 ──audit──▶ 已审计 ──polish──▶ 已体检 ──apply──▶ 已应用
                  │  ▲                                                   │
                  │  └────────────── 人工编辑 / 回滚 .bak.md ────────────┘
                  └──▶ 已定稿（人工拍板，无机器标志位）
```

> 说明：本项目**没有**在文件里写状态字段（无 front-matter、无状态文件），状态完全由「哪个产物文件存在」推导。这是刻意的设计——不加机器状态，也就不会出现「状态与事实不一致」的新故障源。代价是：删掉某个产物文件就会让状态「回退」，属预期行为。

### 4.2 账本状态

| 状态 | 判据 | 由谁推进 | 下一步 |
|---|---|---|---|
| **未建** | `story_state.md` 不存在 | — | `--init-state`（CLI 必跑；Web 写章/审计会自动补跑） |
| **已初始化** | 存在且含 7 小节标题，内容多为「（空）」 | `--init-state` | 写第 1 章 |
| **已同步** | 最近一次写章/补算后已回填本章事实 | 写章流程 ① 第 6 步 | 续写下一章 |
| **滞后** | 正文已写但账本未更新（用了 `--no-state`，或第 6 步失败） | 人发现 | `--state-only --chapter N` 重算 |
| **冲突待裁决** | 账本内出现 `⚠冲突：旧账记X，本章写Y（请作者裁决）` | 模型（规则 9）或审计 | 人工改账本或改正文 |
| **损坏/截断** | 7 小节不全、或末行是不完整标题 | 模型输出被截断、误操作 | 人工补写缺失小节；严重则 `--init-state` 重建（会丢历史） |

> ✅ **2026-09-04 状态更新**：上述截断**已修复**——账本已恢复 7 小节完整（commit `9f84edc`），且写章流程已加入 `validate_state()` 结构校验（截断会被当场拦截，见 `13-变更记录.md` CH-28）。历史记录保留：账本曾于写第 7 章后被模型输出截断（末行停在 `## 关键事件时间线（最近约 10`，缺第 4–7 节），当时按「损坏/截断」处置。

### 4.3 跨流程约束（必须遵守，否则会互相污染）

| 约束 | 原因 | 违反后果 |
|---|---|---|
| 先 ③ 审计、后 ② 去味 | 去味会改句子，改完再审计等于审计改写稿 | 事实错误被文笔修饰掩盖 |
| apply 后必须 re-scan | AI 改 AI 会引入新套话（README 坑 8） | 旧腔没了、新腔来了 |
| 账本处于「滞后/损坏」时不得续写 | 账本是唯一记忆源 | 后续每章都建立在错误前提上 |
| 不要在 apply 之后直接 `--state-only` | 账本已含本章事实，重算会二次叠加 | 计数被重复累加（如回闪次数翻倍） |
| 同一章不要并发跑两个引擎 | 无文件锁（详见 `09-风险清单.md` R-07） | 后写的覆盖先写的，正文/账本错乱 |
