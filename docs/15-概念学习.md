## 第①站：模型（Model）

### 现在什么情况
- novel-ledger **不绑定模型**，只说 OpenAI 兼容协议（`POST {base_url}/chat/completions`）；主通道 `.env` 的 `AGNES_*`（agnes-2.5-flash），备用 `FALLBACK_*`（纸面配置，未实测厂商）。
- 写章/账本更新/审计/去味 L2 都调模型；L1 词表扫描零 token（成本优势）。
- 全调用 `reasoning_effort=low`（防推理模型吞光预算返空，踩坑 1）；`max_tokens=12000` 防截断；主失败自动切备用（须连 model 名一起换，已修 bug）。
- 单章实测约 60s；Agnes 免费额度/资费未核实（04-Q12 挂着）。

### 怎么优化
- 用量记账（usage_log，几十行，纯本地）
- 把 failover 变成真的：花一次小钱实测 DeepSeek 或智谱并留档
- 异构审计 R42：主模型写、备用模型审计
- 分任务模型路由：便宜的干粗活、贵的干精活（代码已支持，未给 UI）

### 怎么用（换厂商）
- Web ⚙ 设置页填 key + 测试连接（实时生效）；CLI `--base-url/--model/--key` 临时切；改 .env 持久切（别提交）
- 判断标准：质量不满意→换贵模型试一章；想省钱→换国产 flash 试一章；**每换必连写 2-3 章再下结论**

### 可以怎么做
- v0.2 加用量统计（小活）
- 近期实测一家备用厂商，把"先记着"变成 docs 待办
- 长期原则：不绑定厂商、不承诺本地模型（零依赖边界）

## 第②站：Agent（智能体）

### 现在什么情况
- Agent = 能自主决定步骤、调工具的 AI（单 agent+工具 / 多 agent 编排两级）。
- novel-ledger **不是 agent，是确定性工作流**：Python 写死顺序（写章→账本→审计），模型不自作主张。这目前是优点（可测可控）。

### 怎么优化
- 偷思想不背框架：大任务拆小步+喂状态（账本已在做）、关键节点人把关（R32 闸口）、多步但确定。
- **不引入** LangGraph/AgentScope 等框架（破坏零依赖、测试难、黑盒）。竞品 Mo-Shen 用框架是从零新项目，情况不同。

### 怎么用（试点形态 = R32 落地）
人机接力流水线：你拍板 → AI 出章纲+200 字试写 → 你确认/改 → AI 写正文 → AI 更新账本 → AI 审计 → 你审章拍板 → 痕迹链存档(R46)。

### 可以怎么做（2026-09-04 拍板）
- **v0.2 引入"轻量多 agent"= 多角色 + 确定性调度 + 人闸口**（多个模型扮演策划/写手/审校，但顺序由代码写死，不引框架、不破坏零依赖）。
- R32 确认关卡：**试写 + 章纲都确认**（防风格跑偏）。
- Q14 自动连写形态：**确定性批处理**（排队逐章写+每章审计，默认关）。
- Q6 技能模板：**"预设流程包"**，作者选一套就跑（模型不自主调工具）。

## 第③站：框架（LangChain / AgentScope 等）

### 现在什么情况
- **未引入，且是刻意不引入**——ADR-1「零第三方依赖」的延伸，`requirements.txt` 不存在。

### 结论（2026-09-04 讨论定稿：不引入，本站可打 ✅）
- 框架（"AI 预制菜料理包"）省的是起步功夫，代价是版本地狱与黑盒化，与"两年后还能跑"的开源目标冲突。
- 本项目核心难点（账本、上下文配方、去味）框架帮不上忙；竞品中用框架者均为从零起步的新项目，半路迁移≈重写。
- 唯一例外：v0.3 向量层（R39）按"可选插件"装 chromadb 属**单件工具**，不等于引入框架，不破坏主路径零依赖。

## 第④站：skill / MCP

### 现在什么情况
- skill = 给 AI 看的"菜谱卡"（把某类活怎么干写成文档喂给 AI）；MCP = AI 连外部工具的"万能插座"。项目两者都未直接使用，但有两处**无师自通的雏形**：①去味词表、账本规矩、写作红线 = 硬编码在代码里的菜谱卡；②HANDOFF 交接文档 = 给接手 AI 的一份 skill。

### 结论与动作（2026-09-04 拍板）
- 方向 = **规则外置**：提示词/词表/账本规矩搬进 `rules/` Markdown 文件，改规则不改代码——随 R32 落地（v0.2）。
- "多套风格包一键切换"（悬疑包/都市包）= v0.4 已拍板的"预设流程包"，不提前做。

## 第⑤站：回溯（改前文之后怎么办）

### 现在什么情况
- **全项目最大的机制缺口**：只有 `.bak.md` 首版备份；"改了第 N 章后，其后所有章节的账本基于旧版、全部失真"——此前无任何机制、任何文档约定。
- 类比：账本记到 9 月发现 3 月记错一笔，后面 6 个月余额全对不上。

### 结论与动作（2026-09-04 拍板）
- **R47**：每写完一章自动存账本快照 `_snapshots/chNNN.state.md`，永不清理（v0.2）。
- **R49**：「从第 N 章重算」命令——拿第 N 章快照当起点，逐章重算其后账本至最新（正文不动，只重算便宜 5 倍以上），一步到底 + 完成报告（v0.3）。
