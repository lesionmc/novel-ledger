v0.7 起项目进入生态分发期：本体留 GitHub，WorkBuddy 侧用 Skill 薄壳获客。

## v0.7 分发三件套

| 文件 | 角色 | 说明 |
|---|---|---|
| `skill/SKILL.md` | 薄壳获客 | WorkBuddy Skill 入口，仅做五场景 CLI 教学（写下一章/断点连写/全书去 AI 味/质检体检/一键备份），不含任何逻辑；用户被引导回 GitHub 本体 |
| `scripts/guard_push.py` | 守卫进程 | 纯标准库、**只读不写**；轮询各书 `tasks.json` 状态与新章增量，变化时推企业微信 webhook。实测：33 章基线识别零报错，首轮 `_SEEN` 基线不推历史 |
| `launch_webview.py` | 桌面壳 | 可选；pywebview 为全项目唯一可选依赖（未装时友好提示并回退浏览器），先拉起 `web/server.py`（端口 8801 已占用则复用）再开窗口 |

## 分发策略

1. **GitHub**：本体与全部文档，Issue 承接反馈；README 保持命令手册最新。
2. **SkillHub（WorkBuddy 推荐市场）**：只发 `skill/SKILL.md` 薄壳，一句话卖点引流，降低试用门槛。
3. **不绑平台**：薄壳里所有命令都是本机 `python scripts/…`，装不装 WorkBuddy 都能跑。

## 分发纪律（承接数据事故教训）

- 每次发版前 `git push`，书稿（chapters/）必须入库；
- `SKILL.md` 永不改写引擎行为，只描述已验证的命令；
- guard_push 的 `WEBHOOK_URL` 只进环境变量/`.env`，不进仓库。

## 备份纪律（数据事故教训）

9/5 整目录被删的教训：**`books/` 内的 `backup_book.py` 只防单书损坏，防不了整目录删除**。它把整本书打包成 zip 留本地，但目录本身没了就全没了。必须再做一层"项目外"的整盘压缩。

**做法（每周一次）**：对 `books/` 与 `.env` 所在的项目根做一次压缩备份，存到**项目之外**的盘/目录，例如 `C:\Users\lhx\Desktop\小说\backups_外部\`（目录名自拟，关键是"项目外"，别和 `novel-ledger/` 同目录）。

**为什么必须项目外**：同目录的备份会跟着被删一起没。项目外的位置（甚至另一块盘/云盘）才是真兜底。

**Windows 任务计划自动跑（每周日）**：新建"任务计划程序"任务，触发器=每周日，操作=启动程序 `powershell.exe`，参数为下面这条命令。可直接复制：

```powershell
# 每周日自动：把整项目根（含 books/ 与 .env）压缩到项目外
$src = "C:\Users\lhx\Desktop\小说\novel-ledger"
$dst = "C:\Users\lhx\Desktop\小说\backups_外部"
$stamp = (Get-Date -Format "yyyy-MM-dd")
$out = Join-Path $dst ("novel-ledger_" + $stamp + ".zip")
# -Force 覆盖上周；如需排除 .git 可先 robocopy 到临时目录再压缩
Compress-Archive -Path $src -DestinationPath $out -Force
```

要点：
- 备份对象至少含 `books/`（书稿）与 `.env`（密钥）——项目根整体压最省心。
- `books/` 已入库 git（9/5 后 `.gitignore` 不再排除 chapters/），但 **`git push` 才是跨机兜底**，本地压缩只是防本机误删。
- 周日前确认 `backups_外部\` 真生成了 zip，别等出事才发现计划没跑。
